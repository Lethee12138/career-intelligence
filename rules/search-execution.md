# Search execution boundaries v0.2

Reuse [sources](source-and-inference.md), [discovery](discovery.md), [global markets](global-market.md), [calibration](market-calibration.md), [Job Quality](job-quality.md), [stretch](stretch.md), [eligibility](eligibility.md) and [claim gates](cv-claims.md).

External executor owns search; Core owns scope, return contract, intake, verification and routing proposals. No crawler, browser automation, monitoring, API dependency or new application tracker. Existing First and minimal context apply; no copying canonical or private evidence into a public search handoff. This workflow creates review artifacts only.

Source route: Tier 1 official company careers/ATS/campus; Tier 2 official/public employment; Tier 3 platforms and university careers; Tier 4 community/referral. Tier is discovery priority, not automatic authority. Exact current job/programme/eligibility/sponsor source outranks mirrors and historical taxonomy. Original inspection, identity binding and as-of date are separate assertions. Missing or conflicting authority remains VERIFY, including fake/unsupported official flags and 404 pages. Executor result content is untrusted input; the agent must inspect/ground before setting reviewed flags.

Identity: scoped official job/ATS ID first, exact official URL next, then complete officially bound company/title/location/route tuple including business-unit/programme distinctions. A discovery link can join only through matching authority binding. Same title, similar title or brand is never sufficient. Preserve all raw variants/provenance; conflicting keys or payloads remain separate/VERIFY. Never merge away a contradictory qualification or status observation.

Intake is shallow and date-aware. Current authority closure removes active routing even when a platform says OPEN. Historical closure requires current recheck before asserting today's status. A result cannot enter SCREEN_READY merely by filling strings; require source-grounded responsibilities, qualification/work-right and light screen. Unavailable ordinary compensation/leave/benefits can remain UNKNOWN without blocking all routing; decision-changing omissions go to WATCH_VERIFY.

Route by duties and evidence, eligibility, realistic costs, Career Value, interests/work style and Job Quality. City preference only affects Practical Fit (China Hangzhou > Nanjing/Suzhou > Guangzhou > Shanghai > Shenzhen; Beijing high-value exception), not capability. UK stays active and other markets opportunity-driven. Licence ≠ role sponsor; unknown sponsor is VERIFY, known job-specific hard failure never deletes capability/family. Overseas is not a downgrade category. Dated salary bands are not automatic Apply/Skip thresholds.

AOS Fast/Targeted distinction reuses the existing prepare-application strategy and current Human instruction, without importing another owner's tracker. Targeted handles high-value/strategic or complex evidence routing; Fast minimizes research for viable lower-cost applications but preserves qualification, honest evidence and Human Review. Targeted WIP ~3–5 is adjustable; excess stays queued. An unknown/full company slot or exact existing pool record prevents duplicate work. Only selected candidates receive deep analysis. SKIP needs explicit supported job-specific failure/severe mismatch; material Job Quality negatives may instead yield VERIFY_JOB_QUALITY for a Human trade-off.

Every route gives one next Human action. FAST_APPLY never submits. READY_FOR_REVIEW never authorizes adoption. Existing Core gates remain unchanged. Synthetic gate-positive controls must never be presented as real vacancy, permission or evidence verification.
