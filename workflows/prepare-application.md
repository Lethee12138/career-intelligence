# /prepare-application

1. Read the same-identity JobAnalysis, source revision, relevant existing evidence and current Job Record. If absent, execute bounded /analyse-job first. Recheck changed/stale sources; historical fixture analysis cannot authorize live preparation.
2. Pass the preparation gate: identified real role, authoritative current OPEN status, all applicable hard qualifications ELIGIBLE, evidence-backed reason for preparation, no known contradictory critical information. For a one-active-application company, existing slot must be clear or belong to this exact role; UNKNOWN/occupied other role blocks active tailoring. Blocked output is `PREPARATION_HOLD` plus reasons/VERIFY actions, no CV claims or packet.
3. Select one proportionate Fast/Targeted strategy based on reviewed analysis. Recommend the existing CV Base and version/reference, select a small project router from allowed evidence, and state why this role. Do not require a full cover-letter/interview/HTML package.
4. Identify strongest evidence, likely recruiter concerns (INFERENCE), gaps and honest responses. Create only claims with a complete requirement → evidence → verified fact → claim chain. UNKNOWN permission/source links produce gaps; preserve them rather than improving the wording into a fact.
5. Offer relevant portfolio references subject to public-use permission. Prepare evidence stories and second-/third-layer follow-ups with answer boundaries. A proposed metrics framework is a future method, never a past result.
6. Only if the target triggers it and completed evidence is available, create the optional packet under [claim rules](../rules/cv-claims.md). Preserve all missing fields and aggregate-vs-event trace limits.
7. Return ApplicationBrief candidate, checklist and VERIFY items using [contracts](../schemas/contracts.md). Stop before material adoption, canonical Save, login, submission, contact, upload or external action. End with `HUMAN_REVIEW_REQUIRED`; this is not approval.
